## Highlights

- **Auth gap spelled out: `insecure` lets a sandbox impersonate anyone ([#3719](https://github.com/kagent-dev/kagent/pull/3719), emoods, opened 11-18, `enhancement`, closed unmerged).** Adds a third controller `mode: deny` beside `insecure`/`trusted-proxy`: the user provider rejects *all* credentials, so only TokenReview service-account tokens (audience `kagent-invocation`) and Substrate Actor credentials authenticate (`serviceAccount` becomes mandatory). The problem statement is the useful part for Enterprise Q&A: the default `insecure` accepts any `X-User-Id` / `?user_id=`, so an agent sandbox on a shared cluster can list other users' sessions and invoke other agents; `trusted-proxy` parses but does **not** verify the JWT. Also makes `helm/kagent/files/nginx.conf` strip those headers for any non-`insecure` mode. **Closed two minutes after opening** — the multi-tenant gap is still open on v1.0.1; live work is [#3018](https://github.com/kagent-dev/kagent/pull/3018).
- **Runtime capacity leak — the "WorkerPool full / nothing answering" symptom ([#3708](https://github.com/kagent-dev/kagent/pull/3708), shashankram, opened 11-17).** Canceled or failed deliveries can leave actors resuming/running with no turn, holding worker capacity. Closes router connections and revokes unused dispatches before delayed cleanup, recovers interrupted resumes, bounded best-effort retries, configurable grace delay (**120 s default, 0 disables, 1 s in CI**); unit + PostgreSQL + E2E, +1430/−208 over 40 files. Stated trade-off: no durable job or recovery scan, so controller restart or retry exhaustion can still strand actors.
- **Single-file install for demos and docs ([#3709](https://github.com/kagent-dev/kagent/pull/3709), Stevenjin8, opened 11-17, +243/−61).** `kagent install` accepts inline configuration instead of separate Helm values files — the one-file demo story on omni-viper gets simpler if it lands (watch interaction with yesterday's #3554 platform-agent render rules).
- **Substrate: OpenShift SCC compatibility ([#180](https://github.com/kagent-dev/substrate/pull/180), adalundhe, opened 11-17, draft).** `restricted-v2` refuses the chart's pinned `runAsUser`/`fsGroup` on **RustFS (10001)** and **k8s-credential-provider (65532)**, so both pods fail admission on OpenShift; the chart leaves them unset when the cluster serves `security.openshift.io/v1`, and plain-Kubernetes rendering stays byte-identical (six value sets verified). Gotchas: remove an `anyuid` grant on the RustFS SA (it outranks `restricted-v2`, assigns no fsGroup → new PVC unwritable), and the raw manifests in `manifests/ate-install/` and `manifests/egress-credential-injection/` **still pin the IDs**. Not yet run on a real cluster.
- **Python/OpenAI harness: tool results were unlabelled UUIDs ([#3716](https://github.com/kagent-dev/kagent/pull/3716), BahaaMattar, opened 11-18, `bug`, fixes #3715).** `FunctionCallOutput` raw items are plain dicts, so `hasattr(raw_output, "call_id")` never matched — every result got a fresh UUID, leaving CLI/MCP transcripts unpaired and UI result cards titled with a UUID; non-JSON output (`ToolOutputText`) failed `ParseDict` and was dropped. Fix keeps a per-run call-id→tool-name map and passes non-JSON through. Same author also opened [#3711](https://github.com/kagent-dev/kagent/pull/3711) (name the model in the memory-summarization request) and [#3718](https://github.com/kagent-dev/kagent/pull/3718) (never send a blank tool-result text block to Bedrock).
- **UI: no way to inspect a Harness or MCPServer ([#3712](https://github.com/kagent-dev/kagent/pull/3712), alan-bentley-pgh, 11-17, draft)** — adds both details pages plus cross-resource links; companion [#3705](https://github.com/kagent-dev/kagent/pull/3705) unifies forms, validation and pickers. Also new: MCP tool-result images in chat [#3246](https://github.com/kagent-dev/kagent/pull/3246), [#3527](https://github.com/kagent-dev/kagent/pull/3527) (UI as an optional 1.x client), [#3706](https://github.com/kagent-dev/kagent/pull/3706) (non-streaming Anthropic with large `max_tokens`), CNCF artwork metadata [.project #3](https://github.com/kagent-dev/.project/pull/3) (jeefy).
